## Security & Operational Recommendations
- Make user-specific routes non-cacheable by default or use a cache key bound to `user_id` or session.
- Enforce hard upper bounds: `MAX_PAGE_ALLOWED` and `MAX_PER_PAGE` to avoid expensive DB OFFSETs.
- For very large page values: prefer keyset pagination or early return of empty response to avoid heavy DB scans.
- Always append a deterministic tie-break sort key (e.g., `id desc`) when primary sorting is not deterministic, so refreshed pages remain stable.
- Normalize canonical URLs and publish them in responses (only one `page` param, one `per_page` param) to reduce cache fragmentation across layers.
- Avoid using `request.args.get('page', type=int)` directly — use the normalizer to ensure consistent behavior across upstream anomalies.
